# 05 AI 讀者書寫規範（11 條）

> 適用：全 host｜載入：無（PROPOSAL；落地後由 CONVENTIONS.md 常駐生效）
>
> 讀者是 AI 模型，不是人。設計原則只有一個：**每一句話都要能被機械驗證或機械執行**——
> 模型換代後，散文語感會漂移，但「檔案存在」「grep 命中」「exit code」不會。

## 1. 檔頭 metadata（HTML comment，不佔注入 token 預算）

每個 `~/.agents/` 常駐檔第一行必為：

```html
<!-- tier: 0 | consumed-by: claude,codex,copilot | generated-from: core/tier0-safety.md | last-verified: 2026-07-07 -->
```

生成部署的目標檔（`dist/`、`~/.codex/AGENTS.md` 等）另加 banner：`<!-- GENERATED by agents-sync @ <git-sha> | source-hash: <hash> | DO NOT EDIT -->`。手改生成檔 = bug；agents-sync no-clobber 會拒絕覆蓋無 banner 的檔並報錯。

## 2. 規則五要素格式

每條規則單行自足：

```
[T0-3] MUST NOT force-push 到 main/master。觸發：git push --force* 且目標分支為 main|master。例外：無。驗證：rules lint + hook audit-bash。
```

五要素 = 穩定 ID + RFC2119 動詞（MUST / MUST NOT / SHOULD）+ 機械觸發條件 + 明示例外（沒有就寫「無」）+ 驗證方式。缺任一要素的規則不得進 tier 檔。

## 3. 規則 ID 永不重編、永不回收

刪除或降級規則時留殼標記：`[T1-7 DEPRECATED→T0-2 2026-07]`。理由：舊 session transcript、commit message、cookbook 條目可能引用舊 ID；重編會讓歷史引用全部斷鏈且無人察覺。

## 4. 跨檔引用只用規則 ID 或檔路徑

禁止散文錨點（「見上方 merge gate 一節」「如前述」）。散文錨點在檔案被生成器重組後靜默失效；規則 ID 與路徑可被 lint 驗證。（實證：DCT repo doc-rot 審計中，錨點解析器掃不到散文符號殘留，須另跑 grep 雙軌。）

## 5. 載入宣稱必附驗證指令

任何「X 會載入 Y」「X 繼承 Y」的句子，同段必附可執行探針指令 + 預期輸出。無法驗證的宣稱必須加 `UNVERIFIED:` 前綴且禁用肯定句式。（實證：Copilot「已自動載入 ~/.claude/CLAUDE.md」一句未驗證肯定句，讓完整 Hard Rules 的取得失守一個月無人察覺——殘存僅英文摘要，見 01 F1。）

## 6. Fingerprint codeword

每個常駐注入檔含恰一句唯一指紋，格式 `FP:<檔名代號>-<年季>`，例 `FP:AGENTS-T0-2026Q3`。用途：context 級載入驗證（`claude -p '複誦 FP 句'` / `codex debug prompt-input` grep / `copilot -p` 禁工具複誦）。檔案級驗證（symlink 存在、hash 相符）不足以證明「進了 context」——兩起事故皆是檔案層正常、context 層死透。

## 7. 名稱引用必過 lint

skill / agent / MCP server / hook 名稱一律 lint 對照實體目錄；手寫清單禁止，索引只准機械生成。（實證：Copilot 9 個死 skill 引用、`chrome-devtoolss` 拼錯，全是手寫清單腐爛。）

## 8. Context 硬預算

tier0 ≤30 行、routing ≤30 行、三家常駐生成總量 ≤10KB；超標 = agents-sync build fail，不是警告。理由：Codex override 事故的根因之一就是「32KB 太長→有人另立短檔→短檔整檔取代長檔」。預算是防止下一次 override 誕生的結構性手段。

## 9. why 一句話 + 出處座標；可機械化者必須下沉

規則的 why 限一句 + 座標（commit SHA / PR 編號 / 審計日期），詳細敘事放 cookbook 或 proposal 附件。凡能寫成 hook / lint / test 的檢查，必須下沉為機械守護並從 prose 移除——prose 只留判斷類知識。

## 10. 語言與句式

zh-TW；術語照 tier2 用詞對照表（建立／物件／佇列；禁「創建／質量／視圖」）；規則句禁隱喻、禁反問；每句單獨抽出仍可執行（模型可能只看到被 grep 出來的單句）。技術名詞與識別字保留原文。

## 11. 版控取代 .bak（`~/.agents` git 化後生效）

三家設定目錄（`~/.claude`、`~/.codex`、`~/.copilot`）的手工 `.bak` 慣例廢止：設定變更一律走 git commit；MUST NOT 再產生 `*.bak*`。既有 .bak 掃 secret 後刪除或歸檔 `attic/`。（實證 2026-07-07：`~/.codex` 累積 26 份 .bak，其中 3 份 `config.toml.bak` 額外複製了同一明文 API key——**備份檔是 secrets 殘留的最大死角**：rotate 正本、忘了 .bak = 白 rotate。.bak 正是「無版控環境長出的手工版控」病徵，git 化後病因消失，慣例應隨之廢止。）驗證：`ls ~/.claude/*.bak* ~/.codex/*.bak* ~/.copilot/*.bak* 2>/dev/null | wc -l` = 0。
